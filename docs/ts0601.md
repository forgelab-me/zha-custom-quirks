# TS0601 PIR (_TZE284_gnpflcoq)

Quirk for a Tuya TS0601 motion sensor (manufacturer `_TZE284_gnpflcoq`) that
exposes presence, temperature, humidity, illuminance, battery, and two
configurable settings (sensitivity and PIR delay).

File: [`zha_custom_quirks/ts0601_pir.py`](../zha_custom_quirks/ts0601_pir.py)

## Exposed entities

| HA entity        | Type          | Detail                                          |
| ----------------- | ------------- | ------------------------------------------------ |
| Motion            | binary_sensor | `device_class: motion`                            |
| Battery           | sensor        | `device_class: battery`, %                        |
| Temperature       | sensor        | `device_class: temperature`, raw value divided by 10 |
| Humidity          | sensor        | `device_class: humidity`                          |
| Illuminance       | sensor        | `device_class: illuminance`                        |
| PIR Sensitivity   | select (enum) | `low` / `middle` / `high`                         |
| PIR Delay         | number        | 10 to 180 (seconds)                               |

## Recommended customization

The quirk's sensors don't set a `unit_of_measurement` or `state_class`, so
Home Assistant won't show units or keep long-term statistics for them out of
the box. Add entries for your entities in `customize.yaml` (referenced from
`configuration.yaml` via `homeassistant: customize: !include customize.yaml`),
adjusting the entity IDs to match your own device:

```yaml
sensor.ts0601_temperature:
  unit_of_measurement: "°C"
  state_class: measurement

sensor.ts0601_humidity:
  unit_of_measurement: "%"
  state_class: measurement

sensor.ts0601_illuminance:
  unit_of_measurement: "lx"
  state_class: measurement

sensor.ts0601_battery:
  unit_of_measurement: "%"
  state_class: measurement
```

## Notes

- The custom `TuyaPIRSensorCluster` cluster uses id `0xEF00` (the standard Tuya manufacturer-specific cluster).
- `skip_configuration()` is used because this type of Tuya device doesn't respond correctly to standard ZCL reporting configuration.
- If your device has a different `manufacturer` than `_TZE284_gnpflcoq` (another variant of the same product), duplicate the file and adjust the identifier in `QuirkBuilder(...)`.
